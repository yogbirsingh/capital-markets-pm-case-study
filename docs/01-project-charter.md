# Project Charter

## Name

Capital Markets Regulatory Reference Data Change

## Background

Financial institutions rely on standardised reference data to identify and process financial instruments consistently across their internal systems and regulatory reporting processes.

A new regulatory requirement requires additional reference data fields to be made available through an existing capital markets data service.

The change must be implemented before a fixed regulatory deadline and requires coordinated delivery across Product, Business Analysis, Development, QA, Operations and external financial institution stakeholders.

## Objective

Deliver the required reference data changes before the regulatory deadline while maintaining data quality, stakeholder alignment and operational readiness.

## Business Need

The change is required to ensure that participating financial institutions can access the additional reference data required for their regulatory reporting obligations.

Failure to deliver the change by the required date could result in:

- Financial institutions being unable to consume the required data
- Increased manual processing or workarounds
- Regulatory reporting disruption
- Reputational impact
- Additional operational effort

## Scope

### In Scope

- Confirm and document the regulatory change requirements
- Agree required reference data fields
- Update the existing data service to support the new fields
- Coordinate development and testing activities
- Validate requirements with relevant stakeholders
- Coordinate User Acceptance Testing (UAT)
- Track risks, issues and dependencies
- Manage changes to agreed scope
- Prepare operational and release readiness
- Deliver the change before the regulatory deadline

### Out of Scope

- Replacement of the existing data platform
- Changes unrelated to the regulatory requirement
- Redesign of financial institutions' internal systems
- Development of new trading functionality
- Changes to unrelated financial products or datasets

## Key Deliverables

1. Approved requirements
2. Agreed delivery plan
3. Updated reference data functionality
4. Completed system and QA testing
5. Completed UAT
6. Operational readiness confirmation
7. Production release
8. Post-delivery retrospective

## Constraints

- Fixed regulatory implementation deadline
- Availability of external financial institution stakeholders
- Dependency on approved requirements before development can complete
- Limited UAT window before production release
- Production changes must satisfy operational readiness requirements

## Assumptions

- Core platform infrastructure is already operational
- Required development resources are available
- External stakeholders will participate in requirement validation and UAT
- No major platform redesign is required
- Test environments will be available according to the delivery plan

## Success Criteria

The project will be considered successful when:

- Required reference data changes are delivered before the regulatory deadline
- Agreed requirements are implemented and tested
- Critical UAT scenarios pass
- No unresolved critical defects remain at release
- Operational readiness is confirmed
- Key stakeholders are informed of release readiness
- Project documentation and outstanding actions are appropriately closed
